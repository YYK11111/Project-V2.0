# Customer Sales Owner Default And Required Design

## Goal

修正客户新增场景下“销售负责人”字段的默认值与校验行为，避免空值提交，并让业务录入符合“客户必须归属到具体销售负责人”的约束。

## Current Context

- 页面 `nest-admin-frontend/src/views/business/crm/customerManage/form.vue` 当前把 `salesId` 默认成空字符串。
- 当前客户表单没有对 `salesId` 做必填校验。
- 后端客户保存链路已增加空字符串到 `null` 的兜底归一化，避免再写出 `sales_id = ''` 导致数据库报错。
- 项目内已有“新增时默认当前登录用户”的前端模式，`taskManage/form.vue` 已通过 `useUserStore().id` 作为默认负责人来源。

## Confirmed Scope

- 仅调整客户表单页 `customerManage/form.vue`。
- 新增客户时：
  - 默认 `salesId = 当前登录用户 id`
  - 字段必填
- 编辑客户时：
  - 保持接口返回的原负责人
  - 不自动改成当前登录用户
- 提交前：
  - 继续走现有表单校验
  - `salesId` 为空时不允许提交

## Non-Goals

- 不调整客户列表页。
- 不改动 `UserSelect` 组件能力。
- 不把同样规则批量扩散到销售机会、合同、互动等其他 CRM 页面。
- 不新增新的后端权限或审批逻辑。

## Approaches Considered

### 方案 A：仅新增时在前端注入默认负责人，并补必填校验

做法：

- 从 `useUserStore()` 读取当前登录用户 `id`
- 在“无客户 id”的新增分支初始化默认表单时，把 `salesId` 设为当前用户 id
- 在 `rules` 中补 `salesId` 的必填规则
- 编辑态继续使用接口返回值

优点：

- 改动最小
- 与现有前端默认负责人模式一致
- 不改变编辑场景已有数据

缺点：

- 规则主要落在前端，接口层只保留现有兜底而不新增“必填拒绝”语义

### 方案 B：前端默认值 + 前后端同时强制必填

做法：

- 前端同方案 A
- 后端客户保存时进一步拒绝 `salesId` 为空

优点：

- 业务约束更完整
- 能覆盖绕过前端直接调接口的调用方

缺点：

- 超出本次最小范围
- 需要明确是否允许历史数据修订场景不传负责人

### Recommendation

采用方案 A。

原因：当前需求明确落在客户表单交互层，且项目已有前端默认当前用户的成熟模式。本次先用最小改动完成“新增默认当前用户 + 必填校验”，同时保留后端已加的空值兜底，既能解决录入问题，也不会扩大改动面。

## Frontend Changes

### 1. 当前用户来源

在 `customerManage/form.vue` 中引入 `useUserStore()`，并派生当前用户 id，统一转成字符串使用。

### 2. 新增场景默认值

默认表单工厂 `defaultForm()` 调整为：

- `salesId` 默认取当前用户 id
- 若当前用户 id 暂时不可用，则回退为空字符串，由必填校验兜底

该默认值只在“新增客户”路径生效，也就是：

- 首次进入新增页
- 新增页在路由切换后重新初始化表单

### 3. 编辑场景保持原值

若存在客户 `id`：

- 仍然调用 `getOne`
- 接口返回什么负责人，就回填什么负责人
- 不做“若为空则自动补当前用户”的修正

### 4. 表单校验

在客户表单 `rules` 中新增：

- `salesId` 必填
- 提示文案为“请选择销售负责人”
- 触发时机使用 `change`

这样即使用户手动清空默认值，也无法提交。

## Data Flow

### 新增客户

1. 用户进入新增客户页
2. 页面初始化默认表单
3. `salesId` 自动写入当前登录用户 id
4. 用户可保留默认值，也可改选其他销售负责人
5. 提交前执行表单校验
6. 若 `salesId` 非空，则调用保存接口

### 编辑客户

1. 用户进入编辑客户页
2. 页面按客户 id 加载详情
3. 表单中的 `salesId` 使用接口返回值
4. 用户若手动清空负责人，提交时会被表单校验拦截

## Error Handling

### 当前用户信息未及时恢复

若页面初始化时用户信息尚未恢复，默认 `salesId` 可能暂时为空。

处理方式：

- 不猜测后端值
- 依赖表单必填校验阻止提交
- 该场景不改变编辑态逻辑

### 用户主动清空默认负责人

若用户在新增页主动清空 `salesId`：

- 表单校验报“请选择销售负责人”
- 不发送保存请求

## Verification

前端验证至少覆盖：

- 新增页默认表单包含当前登录用户 `salesId`
- `salesId` 校验规则存在
- 编辑页仍使用接口返回值，不覆盖成当前用户

运行顺序：

- `npm run type-check`（`nest-admin-frontend`）
- 相关前端窄测试

## Risks And Boundaries

- 本次不补后端“销售负责人必填”强约束，因此接口层仍主要依赖前端校验和已有空值兜底。
- 若后续业务要求 CRM 所有“负责人”字段统一默认当前用户，应单独做跨页面规则治理，而不是在本次需求中顺手扩散。
