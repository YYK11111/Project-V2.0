# Isle Editor 图片块内容能力对齐设计

## 目标

在现有媒体块交互基础上，继续提升 `nest-admin-frontend/src/features/isle-editor/components/media-block/media-block.js` 中**图片块**的内容能力，让它更接近 `Notion` 图片块的使用体验。

本次设计聚焦图片块，不扩散到视频和附件。目标能力包括：

- caption
- alt text
- add link
- full screen / original

本次目标不是继续重做媒体块交互控制层，而是在控制层已经基本成型的前提下，让图片从“上传出来的资源”升级为“真正的内容块”。

## 范围

本次设计覆盖：

- 图片块的 caption 编辑能力
- 图片块的 alt text 编辑能力
- 图片块的 add link 能力
- 图片块的 full screen / original 查看能力
- 与图片块内容能力相关的数据字段与最小测试

本次不覆盖：

- 视频块和附件块的内容能力增强
- 业务页面改造
- 上传接口与后端协议改造
- 图片裁剪、蒙版、对齐控制
- 右键菜单、拖拽句柄系统

## 已确认约束

用户已明确确认：

- 这是“媒体块 Notion 化第二阶段”
- 这轮优先推进**图片内容能力**
- 暂不把同样深度扩展到视频和附件

## 当前现状

当前图片块已经具备：

- 空块、本地上传、链接插入
- 完成态与错误态
- 底部悬浮浮层
- 替换、打开、复制链接、删除

但它还不像 Notion 图片块的核心原因是：

- 缺少图片说明文字（caption）
- 缺少 alt text
- 缺少“点击图片跳转目标”的链接能力
- 缺少更沉浸的查看方式（full screen / original）

## 方案对比

### 方案 A：图片内容能力完整版

做法：

- 一轮完成 caption / alt / add link / full screen

优点：

- 最完整
- 一轮就能让图片块从“资源块”升级成“内容块”

缺点：

- 需要同时处理数据、渲染、控制入口

结论：

- 采用

### 方案 B：只做 caption 与 alt

做法：

- 先只补图片文本相关能力
- link 和 full screen 放下一轮

优点：

- 改动更小

缺点：

- 仍然不像完整的 Notion 图片块

结论：

- 不采用

### 方案 C：先做操作入口，不做真实能力

做法：

- 先做 `•••` 菜单里的入口项
- 具体内容能力后补

优点：

- 结构上更像 Notion

缺点：

- 用户可感知收益有限
- 只是空入口，不解决内容块能力问题

结论：

- 不采用

## 选定方案

选择方案 A：图片内容能力完整版。

原因：

- 这四项能力一起构成图片块成为“内容块”的最小闭环
- 单独拆开做，收益会被摊薄

## 能力设计

### 1. Caption

图片块支持说明文字。

设计要求：

- caption 显示在图片下方
- 属于图片内容层，而不是动作菜单本身
- 可像普通文本一样编辑
- 当没有 caption 时，不强制占位一整行复杂控件

交互建议：

- 初始为空时，可显示轻量占位提示，例如“添加说明”
- 选中图片块后可直接编辑 caption

### 2. Alt text

图片块支持替代文本。

设计要求：

- 不默认显示在正文中
- 通过控制层入口进入编辑
- 数据持久化到图片块属性中

交互建议：

- 在图片块 `•••` 菜单中提供 `Alt text`
- 点开后进入轻量输入态或小面板

### 3. Add link

图片块支持绑定一个点击跳转目标。

设计要求：

- 与“复制链接”区分
- `复制链接` 复制的是图片资源地址
- `Add link` 绑定的是“点击图片后跳转到哪里”

交互建议：

- 在 `•••` 菜单中提供 `Add link`
- 已有链接时显示 `Edit link` 或 `Remove link`

### 4. Full screen / Original

图片块支持更沉浸的查看。

设计要求：

- 用户可查看图片更大版本
- 可打开原图
- 不要求一开始就做复杂图库浏览器

最小实现建议：

- `Full screen`：本地弹出预览层
- `Open original`：新标签打开图片原地址

## 数据结构建议

建议为图片块补充以下字段：

- `caption?: string`
- `alt?: string`
- `link?: string`

其中：

- `caption` 为图片说明文字
- `alt` 为替代文本
- `link` 为点击图片后的目标地址

`full screen` 不一定需要持久化字段，更适合做运行时 UI 状态。

## 控制层与内容层分离

### 控制层负责

- 替换
- 打开原图
- 复制链接
- Add / Edit / Remove link
- Alt text 入口
- Full screen 入口

### 内容层负责

- 图片本身
- caption 显示与编辑

目标：

- 控制层负责动作
- 内容层负责正文表达

## 阶段边界

这轮只做图片块，不扩展到：

- 视频 caption
- 附件说明文字
- 视频 alt/link
- 附件 add link

原因：

- 图片是最典型的内容块
- 视频和附件先共享控制层，不急于同步补内容层

## 测试建议

至少补以下测试：

1. 图片块可保存并回显 caption
2. 图片块可保存并回显 alt
3. 图片块可保存并回显 link
4. 图片块在完成态可触发 full screen / original 入口
5. 图片块新增能力不影响视频和附件现有交互

## 验收标准

满足以下条件视为达成目标：

1. 图片块支持 caption
2. 图片块支持 alt text
3. 图片块支持 add link
4. 图片块支持 full screen / original
5. 图片块整体更像内容块，而不只是上传资源

## 风险与取舍

### 风险 1：caption 与正文编辑边界混乱

取舍：

- caption 只属于图片块内部内容层
- 不让它演化成普通段落节点

### 风险 2：link 能力和复制链接语义混淆

取舍：

- 明确区分：
  - `复制链接` = 复制图片资源地址
  - `Add link` = 设置点击跳转目标

### 风险 3：full screen 方案做太重

取舍：

- 第一阶段只做最小可用的查看层
- 不做图库级别浏览器
