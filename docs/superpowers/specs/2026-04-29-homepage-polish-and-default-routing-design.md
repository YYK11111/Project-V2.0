# 首页视觉打磨、默认跳转与驾驶舱修复设计

## 背景

当前系统已经完成双首页拆分：

1. `/index` 作为用户首页。
2. `/adminindex` 作为系统首页。

同时，系统首页已接入前端路由级权限控制，权限字符为 `dashboard/adminIndex`。

现阶段仍有三类后续工作需要一起收口：

1. 两个首页的视觉层级还偏初版，需要进一步打磨。
2. 根路径 `/` 的默认跳转仍依赖当前菜单首项，而不是显式按首页权限区分管理员与普通用户。
3. “驾驶舱项目下拉为空”的后端修复已在工作区存在代码修改，但尚未独立提交到 `main`。

## 目标

1. 对用户首页 `/index` 做一轮更贴近工作台的视觉打磨。
2. 对系统首页 `/adminindex` 做一轮更贴近驾驶舱的视觉打磨。
3. 将根路径 `/` 的默认跳转规则改为按 `dashboard/adminIndex` 权限显式区分：
   - 有权限默认进入 `/adminindex`
   - 无权限默认进入 `/index`
4. 将“驾驶舱项目下拉为空”的修复作为独立、清晰的小提交并入 `main`。

## 非目标

1. 不重做整套全局布局系统。
2. 不新增新的首页后端聚合接口。
3. 不重构消息中心、项目驾驶舱、项目列表等现有业务模块。
4. 不调整系统首页权限模型本身，继续沿用 `dashboard/adminIndex`。

## 设计原则

### 1. 双风格混合

本次首页打磨采用“双风格混合”策略：

1. 用户首页 `/index` 使用“企业工作台”风格。
2. 系统首页 `/adminindex` 使用“数据驾驶舱”风格。

这样可以同时满足两类目标：

1. 普通用户更高频地处理任务与项目，需要高信息密度和高操作效率。
2. 管理员需要快速感知系统运行概况，需要更强的概览感和数据层次。

### 2. 权限优先于角色名

根路径默认跳转和系统首页访问控制都继续以 `dashboard/adminIndex` 为准，不按 `admin` 角色名硬编码。

这样可以确保：

1. 是否可访问系统首页由实际权限配置决定。
2. 管理员范围可以通过角色配置灵活调整。

### 3. 驾驶舱修复独立收口

“驾驶舱项目下拉为空”的问题虽然与首页打磨无直接耦合，但属于当前明确待收口的已定位修复，应作为独立小改动保留清晰边界，不与首页视觉打磨混成一个提交。

## 首页视觉设计

## 用户首页 `/index`

### 页面目标

用户首页服务“今天要处理什么”的工作视角，强调任务、项目与快捷入口。

### 视觉方向

采用企业工作台风格：

1. 版面更紧凑。
2. 文本信息密度更高。
3. 操作入口更直接。
4. 图表弱化，列表和任务面板优先。

### 建议结构

#### 1. 欢迎区

保留当前欢迎区，但进一步整理层次：

1. 左侧保留头像、问候语、用户名。
2. 增加一句当天工作导语，例如“围绕消息、项目和知识入口开始今天的工作”。
3. 右侧版本和更新时间做成弱信息卡，不压过主体内容。

#### 2. 我的工作摘要

从当前三张基础卡片扩充为更完整的工作台摘要：

1. 当前待办。
2. 当前待阅。
3. 参与项目。
4. 我负责项目。

如果现有接口短期拿不到“我负责项目”可靠计数，可先通过参与项目列表中的负责人字段做前端最小统计；若真实返回结构不足，再在实现时退回到三卡，但布局预留四卡能力。

#### 3. 我的待办 / 我的待阅

强化列表的工作属性：

1. 每条保留标题与时间。
2. 增加来源标签或状态点。
3. 空状态更温和、统一。
4. 点击统一进入消息中心对应页面。

#### 4. 我参与的项目

项目卡片保持轻量，但层次更清晰：

1. 项目名与状态在顶部形成主副信息。
2. 中部展示负责人、进度。
3. 底部保留进度条。
4. 如字段可用，可增加一行“风险/健康提示”。

#### 5. 快捷入口

入口区更像操作抽屉：

1. 消息中心。
2. 项目列表。
3. 知识中心。
4. 个人中心。

视觉上弱于摘要卡和任务面板，但保持高可点击性。

## 系统首页 `/adminindex`

### 页面目标

系统首页服务“系统管理者现在该关注什么”的视角，强调系统状态、管理动作、趋势和后台入口。

### 视觉方向

采用数据驾驶舱风格：

1. 概览区更强。
2. 卡片数字对比更明显。
3. 分区更清楚。
4. 管理入口与趋势图有更强层级感。

### 建议结构

#### 1. 顶部 Hero

将当前系统首页欢迎区强化为总览头部：

1. 左侧保留“系统首页”标题。
2. 增加一句系统运行摘要。
3. 右侧保留版本与更新时间。
4. 通过更明显的留白、字号、色彩区分出“系统首页”和普通用户首页。

#### 2. 系统概览

保留并强化当前概览卡片：

1. 当前在线人数。
2. 今日访问量。
3. 登录日志总量。
4. 用户总数。

这部分适合作为首屏最重要的数字区。

#### 3. 管理工作摘要

保留并增强管理摘要卡片：

1. 未读系统消息。
2. 当前待办。
3. 当前待阅。
4. 菜单权限节点。

这组卡片更偏“管理动作感知”，不与系统概览混在一起。

#### 4. 系统管理快捷入口

保留现有 7 个入口，但提升入口区层次：

1. 用户管理。
2. 角色管理。
3. 菜单管理。
4. 系统配置。
5. 在线用户。
6. 登录日志。
7. 系统日志。

入口卡片要更统一、更像驾驶舱里的操作面板。

#### 5. 趋势图区

保留：

1. 访问趋势。
2. 用户地区分布。

但应在视觉上位于概览和入口区之后，作为监控补充层，而不是首屏主角。

## 默认跳转设计

### 当前问题

当前根路径 `/` 的跳转仍依赖动态菜单中的“第一个可见路由”。这意味着：

1. 默认首页会受菜单排序影响。
2. 管理员和普通用户不会被显式区分。

### 目标规则

根路径 `/` 的默认跳转按 `dashboard/adminIndex` 权限显式判断：

1. 如果用户权限包含 `dashboard/adminIndex`，则默认跳转到 `/adminindex`。
2. 否则默认跳转到 `/index`。

### 适用范围

该规则应覆盖：

1. 已登录用户访问 `/`。
2. 登录成功后从 `/login` 或恢复场景回到根路径 `/`。
3. 初始化动态路由后没有命中明确业务路径、落回根路径 `/` 的情况。

### 设计要求

1. 不改变已有“直接访问明确路径”的行为。
2. 只重写 `/` 的默认落点。
3. 权限判断复用现有前端权限集合 `useUserStore().permissions`。

## 驾驶舱项目下拉修复收口

### 已定位根因

当前“驾驶舱项目下拉为空”的修复已在代码里体现：

`nest-admin/src/modulesBusi/projects/service.ts`

`getCockpit()` 中应使用：

```ts
const rawProjects = projectListRes?.list || [];
```

而不是读取不存在的 `data` 字段。

### 收口策略

1. 保持该修复逻辑不与首页视觉打磨混成一个功能提交。
2. 作为独立小提交并入 `main`。
3. 若尚未补测试，应补最小回归测试，证明 `getCockpit()` 使用 `list()` 的 `list` 字段生成项目选项。

## 实现边界

本轮实现建议分成两条清晰链路：

### 链路 A：首页前端打磨

涉及：

1. 用户首页样式与卡片层级优化。
2. 系统首页样式与卡片层级优化。
3. 根路径 `/` 的默认跳转规则。
4. 首页相关前端测试与类型检查。

### 链路 B：驾驶舱修复提交

涉及：

1. 后端 `ProjectsService.getCockpit()` 的 `list` 字段读取修复。
2. 对应最小测试。
3. 独立提交到 `main`。

## 风险与控制

1. 风险：首页视觉打磨过度，破坏当前已通过的结构测试。
   - 控制：保留现有功能区块名称，只优化层级和样式，不随意改动区块语义。

2. 风险：默认跳转规则影响已有恢复路径逻辑。
   - 控制：仅在 `to.path === '/'` 场景下重写默认落点，不动明确业务路径恢复逻辑。

3. 风险：管理员默认首页与菜单首项不一致，出现认知差异。
   - 控制：显式把 `/` 的首页落点和 `dashboard/adminIndex` 权限绑定，而不是依赖菜单排序。

4. 风险：驾驶舱修复和首页改造同时提交，后续回滚困难。
   - 控制：坚持独立提交。

## 验证目标

### 首页前端

实现后应验证：

1. `/index` 的用户首页视觉层级更清晰。
2. `/adminindex` 的系统首页更有驾驶舱感。
3. 普通用户访问 `/` 默认进入 `/index`。
4. 拥有 `dashboard/adminIndex` 权限的用户访问 `/` 默认进入 `/adminindex`。
5. 无权限用户直接访问 `/adminindex` 仍被拦截到 `/401`。
6. 首页相关测试与 `type-check` 继续通过。

### 驾驶舱修复

实现后应验证：

1. 驾驶舱项目选择下拉不再为空。
2. 回归测试通过。
3. 修复作为独立提交入 `main`。

## 预期结果

最终系统会得到三项明确改进：

1. `/index` 成为更成熟的用户工作台首页。
2. `/adminindex` 成为更有层次感的系统管理首页。
3. `/` 的默认落点不再依赖菜单排序，而是按实际权限明确分流。

同时，“驾驶舱项目下拉为空”的问题也会作为独立修复被明确提交到 `main`，避免和首页优化混在一起。
