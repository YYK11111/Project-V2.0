# Isle Editor Notion 风格媒体块设计

## 目标

补齐 `nest-admin-frontend/src/features/isle-editor/components/IsleArticleEditor.vue` 中图片、视频、附件三类媒体块，使其在知识中心编辑器里形成接近 `Notion` 的原位块卡片体验：

- 以本地文件上传为主入口
- 保留链接插入作为次级入口
- 插入动作直接在正文当前位置生成块，不先弹独立对话框
- 上传、失败、重试、替换、删除都在原块内完成
- 保存后在查看态保持稳定展示，不退化成裸链接或临时占位

本次目标不是重做整个富文本编辑器，而是在现有 `image`、`video`、`attachment` 节点和 `media-block.js` 基础上，把媒体块补齐成产品级可用能力。

## 范围

本次设计覆盖：

- 工具栏与 slash 菜单触发图片、视频、附件块插入
- 媒体块的空态、上传中、完成态、失败态交互
- 本地文件上传与链接插入两类入口
- 图片、视频、附件在编辑态与查看态的展示统一
- 媒体块 attrs 结构与 `useIsleUpload.ts` 返回数据对齐
- 与媒体块相关的最小测试补充

本次不覆盖：

- 拖拽文件到编辑器空白区域直接上传
- 多文件批量一次插入多个块
- 图片裁剪、缩放拖拽手柄、字幕说明文字
- 视频封面单独上传与视频转码
- 附件重命名持久化
- 协同编辑、版本对比、评论批注

## 已确认约束

用户已明确确认：

- 目标体验以 `Notion` 风格为主
- 插入结果必须是原位块卡片，不是先弹窗再写入正文
- 本地文件上传是主入口
- 链接插入保留，但作为次级入口
- 三类媒体块一起完成，不拆成多次迭代

## 当前现状

当前代码已经具备以下基础：

- `image.js`、`video.js`、`attachment.js` 已定义为独立 block node
- 三类节点都已接入统一 `media-block.js`
- `media-block.js` 已支持文件选择、URL 输入、上传中、失败态、打开、删除
- `useIsleUpload.ts` 已接入项目 `/upload` 接口，并能返回图片、视频、附件三类地址
- 查看态 `IsleArticleViewer` 已能渲染图片、视频、附件节点

当前问题不在于“完全没有实现”，而在于“没有形成稳定产品交互”：

- 工具栏 / slash 到媒体块的插入路径不够顺畅
- 媒体入口没有收敛成统一的原位空块体验
- 本地上传虽然有底子，但离 Notion 风格还差一层完整状态流
- 三类媒体块的展示与动作区不够统一
- 失败、替换、链接插入的体验偏技术组件，不像知识卡片块

## 方案对比

### 方案 A：只修上传链路

做法：

- 保持现有 UI 结构不变
- 只确保本地图片、视频、附件上传成功
- 少量补充错误态和查看态回显

优点：

- 改动最小
- 风险最低

缺点：

- 只能解决“能传”，不能解决“块体验不成立”
- 不符合已确认的 Notion 风格目标

结论：

- 不采用

### 方案 B：插入前弹面板，面板内选择本地或链接

做法：

- 用户点击工具栏或 slash 后先弹出轻面板
- 在面板里选择上传本地文件或输入 URL
- 确认后再插入块

优点：

- 实现思路直观
- 容易把本地和链接入口放在同一处

缺点：

- 与 `Notion` 的“先有块，再在块里完成内容填充”体验不一致
- 会打断用户当前编辑上下文

结论：

- 不采用

### 方案 C：统一原位媒体块卡片

做法：

- 工具栏或 slash 先在光标处插入一个对应类型的空块
- 空块内直接提供“上传本地文件”和“通过链接插入”
- 上传、失败、替换、打开、删除都在原块内完成
- 成功后原位转换为稳定卡片

优点：

- 最接近用户要求的 Notion 风格
- 三类媒体块交互模型一致
- 可最大化复用现有 `media-block.js`
- 后续扩展拖拽、批量插入、说明文字时路径清晰

缺点：

- 需要明确整理块状态与动作边界
- 要补更多测试

结论：

- 采用

## 选定方案

选择方案 C：统一原位媒体块卡片。

原因：

- 它是唯一同时满足“本地上传为主、保留链接、原位块卡片、三类块统一体验”的方案
- 当前代码已经有统一 `media-block.js`，更适合在现有结构上升级而不是拆散重做

## 设计原则

### 1. 入口只负责创建块

- 工具栏图片、视频、附件按钮只负责插入对应空块
- slash 菜单选择图片、视频、附件时也只负责插入空块
- 入口层不直接承担上传或 URL 表单逻辑

这样可以把插入动作和媒体内容填充分离，保持编辑体验稳定。

### 2. 所有动作都在原块内完成

- 上传本地文件
- 链接插入
- 重试
- 替换
- 打开
- 删除

都必须在同一个块节点上完成，不通过删块重建来切换状态。

### 3. 三类块统一状态机

统一保留四种状态：

- `idle`
- `uploading`
- `done`
- `error`

允许的状态流：

- `idle -> uploading -> done`
- `idle -> done`（链接插入）
- `uploading -> error`
- `error -> uploading -> done`

### 4. 编辑态和查看态结构尽量一致

- 编辑态和查看态使用相同的节点数据结构
- 编辑态比查看态多动作区、输入区和错误态控制
- 查看态保留预览与元信息，不退化成纯文本或裸链接

### 5. 只做一期刚需能力

本次只把核心媒体块打通，不引入超出目标的高级块编辑能力。

## 交互设计

### 插入行为

当用户点击工具栏图片、视频、附件按钮，或在 slash 菜单中选择对应条目时：

1. 在当前光标位置插入一个对应类型的空媒体块
2. 空块默认状态为 `idle`
3. 空块直接展示两个主动作：
   - `上传本地文件`
   - `通过链接插入`

不弹出独立对话框，不跳出正文上下文。

### 空块态

空块结构：

- 块图标或类型标识
- 一行简短说明文字
- 主按钮：上传本地文件
- 次按钮：通过链接插入

点击“通过链接插入”后，在当前块内展开 URL 输入区，而不是弹窗。

### 上传中

用户选择本地文件后：

- 原块立即切到 `uploading`
- 显示文件名、文件类型、大小
- 显示上传中状态文案
- 操作区在上传期间禁用重复提交

本次不要求实现真实百分比进度，只要求有稳定的上传中占位状态。

### 成功态

上传成功或 URL 确认后，块更新为 `done`。

要求：

- 在原块内原位更新 attrs
- 不更换节点实例，不删除后重插
- 成功后出现对应媒体预览和动作区

### 失败态

上传失败时：

- 块状态变为 `error`
- 保留原块位置与已知文件信息
- 显示错误文案
- 提供 `重试上传`
- 允许直接 `替换文件` 或 `删除`

失败块不能自动消失，也不能强制用户重新从工具栏插入。

## 三类媒体块的具体表现

### 图片块

完成态结构：

- 大图预览为主体
- 底部轻量信息区：文件名为主，mime/大小为辅
- 选中块时显示动作条

支持动作：

- 替换
- 打开原图
- 复制链接
- 删除

空态和失败态：

- 空态显示上传/链接入口
- 失败态保留缩略占位、错误文案和重试入口

### 视频块

完成态结构：

- 上方视频预览区
- 下方信息区：文件名、mime、大小
- 动作条比图片块更明确

支持动作：

- 替换
- 打开源视频
- 删除

本次不额外开放视频封面编辑，但继续保留 `poster` 字段兼容后续扩展。

### 附件块

完成态结构：

- 左侧文件类型标识
- 中间文件名与元信息
- 右侧或底部动作区

支持动作：

- 打开
- 替换
- 复制链接
- 删除

查看态必须保持为文件卡片，不退化为普通超链接。

## 数据结构

继续使用当前节点 attrs 体系，但收敛为稳定字段。

### 图片 attrs

- `src`
- `alt`
- `title`
- `name`
- `size`
- `mime`
- `width`
- `status`
- `error`

### 视频 attrs

- `src`
- `poster`
- `title`
- `name`
- `size`
- `mime`
- `width`
- `status`
- `error`

### 附件 attrs

- `url`
- `title`
- `name`
- `size`
- `mime`
- `ext`
- `status`
- `error`

本次不新增复杂字段模型，优先把现有字段的状态流跑通。

## 职责划分

### `toolbar-menu` / slash 菜单

负责：

- 触发插入空块

不负责：

- 打开独立上传弹窗
- 直接执行业务上传

### `image.js` / `video.js` / `attachment.js`

负责：

- 定义节点 schema
- 提供插入空块和更新 attrs 所需命令入口

不负责：

- 渲染复杂交互 UI
- 调用上传接口

### `media-block.js`

负责：

- 空态、上传中、成功态、失败态 UI
- 本地文件选择
- 链接输入与确认
- 替换、重试、打开、复制链接、删除
- 根据节点类型渲染不同预览与元信息

它是本次改造的主战场。

### `useIsleUpload.ts`

负责：

- 调用项目上传接口
- 统一规范图片、视频、附件返回值
- 规范化上传地址

建议补充：

- 附件补齐 `ext`
- 三类返回值统一包含 `name`、`size`、`mime` 的兜底合并逻辑

### `IsleArticleViewer.vue`

负责：

- 只读展示图片、视频、附件卡片
- 保持与编辑态完成态一致的主要视觉结构

## 错误处理

需要覆盖以下错误：

- 上传接口返回非 `200`
- 上传返回缺少 URL
- URL 输入为空
- URL 输入后返回非法结果
- 本地文件再次替换时覆盖旧 attrs 不完整

策略：

- 上传失败只更新当前块 `status=error`
- 不抛弃节点
- 错误信息优先展示在块内

## 测试设计

至少补以下测试：

1. 工具栏或 slash 插入媒体时创建空块，而不是立即要求 URL
2. 空块点击本地上传后进入 `uploading`
3. 上传成功后在原块上更新 attrs，节点不重建
4. 上传失败后保留块并展示重试入口
5. 链接插入在原块内确认后进入 `done`
6. 附件查看态保持卡片，不退化成裸链接
7. 图片、视频、附件完成态都能回显文件名和元信息

## 验收标准

满足以下条件视为达成目标：

1. 用户可通过工具栏或 slash 在正文中插入图片、视频、附件空块
2. 每个空块都可选择本地文件或通过链接插入
3. 本地文件上传时能原位显示上传中状态
4. 上传成功后在原块中展示稳定卡片
5. 上传失败后原块保留，可重试、替换或删除
6. 保存后再次打开知识内容时，媒体块能稳定回显
7. 查看页中的附件仍为卡片，图片和视频有可用预览

## 实施顺序建议

1. 统一节点插入命令，改成插入空块
2. 收敛 `media-block.js` 的空态和状态机
3. 补齐本地上传与链接插入在原块内的行为
4. 补齐三类块的完成态 UI 和动作区
5. 校准查看态结构与样式
6. 增补测试并回归知识中心编辑 / 查看页

## 风险与取舍

### 风险 1：块内动作过多导致组件继续膨胀

取舍：

- 本次允许 `media-block.js` 继续承担主逻辑
- 但只补当前目标所需动作，不扩展到 caption、右键菜单等二期能力

### 风险 2：编辑态和查看态样式不一致

取舍：

- 先对齐结构和信息层级
- 不要求两端完全共用同一组件

### 风险 3：上传适配器返回信息不足

取舍：

- 以文件本地 `name`、`size`、`mime` 作为前端兜底
- 不依赖后端新增字段

## 不做事项

以下内容明确留到后续版本：

- 拖拽文件进入编辑器直接上传
- 一次选择多个文件自动插入多个块
- 图片说明文字和标题编辑
- 视频封面编辑
- 附件图标按文件类型精细映射
- 上传百分比和取消上传
- 块级右键菜单和拖拽手柄菜单
