# 人员选择器布局设计

## 目标

重构 `nest-admin-frontend/src/components/UserSelect.vue` 的人员选择器布局，让部门筛选和人员选择在人员数量较多时仍然易于扫描、筛选和回显。

本次目标是把当前“部门筛选 + 人员列表 + 已选区”改成更稳定的工作区结构，重点解决：

- 长部门名和长字段名导致的撑开问题
- 人员卡片过大、单列展示导致的扫描效率低问题
- 已选区域占用中间主操作区宽度的问题

## 已确认约束

- 左侧必须是部门树，不再使用部门下拉框
- 点击部门只做过滤，不做默认选择
- 部门过滤默认穿透下级，即展示当前部门及其下级部门人员
- 人员展示必须保留卡片，不改成表格或纯列表
- 人员卡片采用 4 列密度布局
- 已选区域放到底部，不放右侧

## 当前问题

当前人员选择器存在两个主要问题：

1. 部门筛选区不是树结构，层级感弱，难以快速定位部门。
2. 人员区卡片偏大，信息密度不足，人员多时需要频繁滚动。

此外，已选区域占据横向空间后，会进一步压缩候选人员区，影响整体可用性。

## 选定方案

### 1. 整体布局

采用三段式布局：

- 顶部：搜索工具栏
- 中部：左侧部门树 + 右侧人员卡片区
- 底部：已选区域

这个结构的目的，是把横向空间尽量留给候选人员区，同时让已选结果独立呈现，不干扰筛选与浏览。

### 2. 部门树

左侧使用真正的部门树，支持：

- 展开 / 收起
- 树内搜索
- 节点点击

节点点击后的行为：

- 仅更新候选人员过滤条件
- 不自动勾选人员
- 不清空已选人员

默认规则：

- 选择某部门后，候选人员范围包含该部门及其下级部门
- 不额外暴露复杂层级筛选

### 3. 人员卡片区

人员区保持卡片形式，但改成高密度网格。

布局规则：

- 固定 4 列
- 卡片高度约 60px
- 卡片内容控制在两行以内
- 仅保留必要信息：
  - 姓名
  - 工号 / 账号
  - 所属部门简写

选中态规则：

- 卡片高亮显示
- 允许单选或多选模式复用同一套布局
- 单选时选择新人员替换旧人员
- 多选时保持累积选择

### 4. 已选区域

已选区域放在页面底部，独立于中部候选区。

内容规则：

- 显示已选人数
- 支持单个移除
- 支持清空全部
- 支持回显已有值

展示形态：

- 多选时使用紧凑标签 / 小卡片
- 单选时只展示当前选中项

### 5. 搜索规则

顶部搜索栏支持按以下字段过滤：

- 姓名
- 工号
- 账号

搜索范围基于当前部门穿透后的候选人员池，不影响底部已选结果。

## 数据流

1. 打开选择器后加载部门树和可选人员数据。
2. 默认不选中任何部门和人员。
3. 用户点击部门树节点后，更新部门过滤条件。
4. 候选人员按“当前部门 + 下级部门”范围过滤，再叠加关键词过滤。
5. 用户点击人员卡片后，将其加入已选区。
6. 底部已选区单独维护，不因部门切换而丢失。

## 空态与边界

- 未选部门时，默认展示全部候选人员
- 部门下无人员时显示空态
- 搜索无结果时显示空态
- 已选为空时底部显示空态

## 范围

本次只处理人员选择器结构、布局、过滤和已选区交互，不扩展到：

- 最近联系人
- 群组页签
- 复杂高级筛选
- 虚拟滚动
- 组织外的其他选择器形态

## 第一阶段交付

第一阶段完成后，人员选择器应满足：

- 左侧部门树可用
- 中部 4 列卡片可用
- 默认穿透下级部门
- 不默认选择人员
- 已选区固定在底部
- 搜索和回显正常
