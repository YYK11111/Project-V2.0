# Isle Editor 正文滚动工作台设计

## 目标

优化 `nest-admin-frontend/src/features/isle-editor/components/IsleArticleEditor.vue` 的编辑工作台布局，让知识编辑器在编写长文时：

- 左侧目录固定
- 顶部工具栏固定
- 只有正文编辑区域独立滚动

本次目标不是重做知识中心业务页面，而是只在编辑器组件内部建立一个更稳定的“工作台”布局，避免正文越写越长时把工具栏和目录一起顶走。

## 范围

本次设计覆盖：

- `IsleArticleEditor.vue` 的内部三段式布局调整
- 编辑器内部高度策略
- 左侧目录与正文滚动区域的滚动边界
- 移动端下目录与正文区域的响应式行为

本次不覆盖：

- `aev.vue` 的业务表单区改造
- 页面整体工作区布局重做
- 知识中心卡片结构和治理区块调整
- 目录内容生成逻辑
- 工具栏按钮能力本身的增删

## 已确认约束

用户已明确确认：

- 只做编辑器部分功能，不和业务页面混在一起
- 目标是“目录和工具栏都固定，只有正文中间滚动”
- 不希望正文无限向下撑高，影响上方工具栏使用

## 当前现状

当前 `IsleArticleEditor.vue` 已具备以下结构：

- 左侧目录 `isle-article-editor__toc`
- 右侧主区域 `isle-article-editor__main`
- 主区域中包含 `toolbar` 和 `scroll`

但当前整体高度策略仍偏“自然撑开”，当正文较长时，用户感知上会像整个编辑器一直向下推，导致：

- 目录不再稳定停留在视野里
- 工具栏离光标区域越来越远
- 编辑时需要反复回滚到上方操作按钮

## 方案对比

### 方案 A：编辑器内三区固定

做法：

- 编辑器组件内部定义一个可控高度
- 左侧目录独立滚动
- 顶部工具栏固定在主区域顶部
- 正文作为唯一主要滚动容器

优点：

- 最符合当前目标
- 完全限定在编辑器内部
- 对业务页面依赖最小
- 可控性最好

缺点：

- 需要确定合理的高度策略

结论：

- 采用

### 方案 B：工具栏 sticky，正文继续自然撑开

做法：

- 保持当前整体高度模式
- 只给工具栏加 `position: sticky`

优点：

- 改动小

缺点：

- 容易受外层 `overflow` 容器影响
- 目录固定体验仍然不足
- 长文场景下滚动层级容易混乱

结论：

- 不采用

### 方案 C：整页工作台模式

做法：

- 把业务页中的编辑器区域整体提升为视口级工作台

优点：

- 体验最完整

缺点：

- 已经越过“只做编辑器部分”的边界
- 会牵涉业务页面结构改造

结论：

- 不采用

## 选定方案

选择方案 A：编辑器内三区固定。

原因：

- 完全符合“只做编辑器能力”的边界
- 不要求业务页面配合改造
- 能同时满足“目录固定 + 工具栏固定 + 正文独立滚动”三项目标

## 布局设计

### 1. 工作台结构

保持当前 DOM 结构，但明确三段职责：

- `isle-article-editor__layout`
  - 编辑器整体工作台容器
- `isle-article-editor__toc`
  - 左侧目录栏
- `isle-article-editor__main`
  - 右侧主工作区
  - `isle-article-editor__toolbar`
  - `isle-article-editor__scroll`

其中：

- `toolbar` 不参与正文滚动
- `scroll` 是正文唯一主要滚动容器
- `toc` 自己独立滚动

### 2. 高度策略

编辑器整体工作台不再只依赖内容自然撑开，而是采用可控高度区间。

建议桌面端：

- `min-height: 640px`
- `height: clamp(640px, 72vh, 980px)`

目标：

- 文档较短时仍保留稳定工作区高度
- 文档较长时不再无限向下撑高
- 在大屏下不至于过矮，在小屏下不至于占满整个页面

### 3. 滚动边界

正文滚动统一收敛到：

- `isle-article-editor__scroll { overflow: auto; }`

同时约束：

- `layout` 不负责正文主滚动
- `main` 不再承担正文主滚动
- `content` 只负责宽度与内边距，不负责滚动

这样可以避免多层滚动容器叠加，导致工具栏或目录“看起来固定但实际被推走”。

### 4. 目录区策略

左侧目录栏采用独立滚动：

- `overflow: auto`

目标：

- 长目录不会继续推高整个编辑器
- 目录本身在视野中保持稳定位置

### 5. 工具栏策略

工具栏不使用 `position: sticky` 作为主方案。

原因：

- 只要 `toolbar` 放在正文滚动容器 `scroll` 外面，它天然就是固定的
- 比 `sticky` 更稳定，更少受到外层 `overflow`、层叠上下文影响

## 响应式策略

### 桌面端

- 左侧目录常驻显示
- 工具栏固定
- 正文独立滚动

### 平板与移动端

移动端不强制目录常驻。

建议：

- 目录折叠或收窄
- 工具栏继续保留在上方
- 正文滚动区高度相应缩短

目标：

- 保留工作台思路
- 避免左侧目录挤压正文宽度

## 交互结果预期

做完后，用户在长文编辑时应感知到：

1. 光标持续在正文区域向下移动，但工具栏始终在同一位置可见
2. 左侧目录不会随着正文变长而一起离开视野
3. 编辑器像一个独立工作台，而不是一块不断被页面撑开的富文本区域

## 职责边界

### 编辑器组件负责

- 工作台高度策略
- 目录固定与独立滚动
- 正文区域独立滚动
- 工具栏固定在主区域顶部

### 业务页面不负责

- 给编辑器补 sticky 工具栏
- 通过页面外层高度 hack 修正滚动体验
- 在业务页里单独重做目录布局

## 测试与验证建议

至少补以下验证：

1. 编辑器结构仍包含 `toc / toolbar / scroll` 三层职责
2. 正文滚动容器保持为 `isle-article-editor__scroll`
3. 目录存在独立滚动能力
4. 移动端样式下目录不会继续强占主内容宽度

## 验收标准

满足以下条件视为达成目标：

1. 正文很长时，工具栏不随正文一起被顶走
2. 左侧目录在桌面端保持稳定可见
3. 正文滚动集中在编辑器内部，而不是继续无限推高整个编辑器
4. 业务页 `aev.vue` 无需为此增加额外布局 hack

## 风险与取舍

### 风险 1：高度设太死，影响不同屏幕体验

取舍：

- 使用 `clamp()` 区间高度，而不是固定像素值

### 风险 2：移动端目录与正文挤压

取舍：

- 移动端不强保目录常驻，优先保证正文书写区域

### 风险 3：多层滚动容器导致交互混乱

取舍：

- 明确只保留正文一个主滚动容器，目录一个侧栏滚动容器
