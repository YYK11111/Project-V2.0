# 双首页设计：用户首页与系统首页

## 背景

当前前端首页统一使用 `nest-admin-frontend/src/views/index/index.vue`，内容偏通用轻量看板，主要展示用户欢迎区、访问量、在线人数、地区分布与访问趋势。

这套首页不能区分不同角色的工作目标：

1. 普通业务用户更关心“我今天需要处理什么”，如待办、待阅、参与项目、即将到期事项。
2. 系统管理员更关心“系统当前是否正常、需要处理哪些管理动作”，如在线用户、登录趋势、系统管理入口、系统消息与审批概览。

因此首页需要拆分为两个明确的页面与路由，而不是继续在一个页面里堆叠两类不同目标的信息。

## 目标

1. 将当前统一首页拆分为两个明确页面：`/index` 与 `/adminindex`。
2. `/index` 作为“首页”，服务普通用户工作视角，重点展示待办任务、参与项目和个人工作入口。
3. `/adminindex` 作为“系统首页”，服务管理员管理视角，重点展示系统管理信息和管理入口。
4. 两个页面都需要显示在系统导航结构中，而不是隐藏路由。
5. `/adminindex` 的访问权限以角色管理中的实际权限配置为准，不按“超级管理员角色名”硬编码。

## 非目标

1. 不在本次设计中重做整个布局系统。
2. 不强制要求后端新建首页聚合接口，优先复用现有接口。
3. 不在本次设计中重做消息中心、项目驾驶舱、审批页等已有业务页面。
4. 不通过单页面条件渲染来混合用户首页与管理员首页。

## 方案选择

### 方案 A：两个独立路由、两个独立页面

1. `/index` 对应用户首页。
2. `/adminindex` 对应系统首页。
3. 通过菜单配置分别展示为“首页”和“系统首页”。

优点：

1. 角色职责边界最清晰。
2. 两套页面可以独立演进，避免单页逻辑臃肿。
3. 后续更容易做细分权限、埋点和独立样式优化。

缺点：

1. 如果有重复卡片，可能需要少量复用抽取。

### 方案 B：一个首页内按权限切换两种内容

优点：

1. 只维护一个页面文件。

缺点：

1. 页面职责混杂。
2. 用户首页与系统首页很容易互相污染。
3. 随着需求增加会快速变得难维护。

### 方案 C：一个首页壳 + 两个子面板

优点：

1. 结构上比单页切换更干净。

缺点：

1. 用户已经明确要求两个页面与两个路由。
2. 实际复杂度并不比独立页面低多少。

## 最终设计

采用方案 A：新增并维护两个独立首页。

1. `/index`：用户首页，导航名称为“首页”。
2. `/adminindex`：系统首页，导航名称为“系统首页”。

## 路由与权限设计

### 路由

1. 保留 `/index`，但内容重构为用户首页。
2. 新增 `/adminindex` 页面。
3. 两个页面都配置为可见路由，显示在导航结构中。

### 权限

1. `/index` 为常规登录后可访问页面。
2. `/adminindex` 不按“是否超级管理员角色”硬编码判断。
3. `/adminindex` 的可见与可访问范围，以角色管理中分配的权限为准。

推荐增加单独权限字符，例如：`dashboard/adminIndex`。

这样有两个好处：

1. 不需要依赖零散系统管理权限间接推导是否能看系统首页。
2. 菜单、路由、按钮和后续页面能力控制都能复用统一权限字符。

## 用户首页设计

### 页面目标

用户首页服务“我今天要处理什么”的工作视角，突出个人任务和项目参与情况，而不是系统层统计。

### 页面结构

建议用户首页按以下区域组织。

#### 1. 顶部欢迎区

展示：

1. 用户头像、姓名、时间问候。
2. 当前版本与更新时间。
3. 进入个人中心的快捷入口。

该区域保留当前首页中已存在的个人欢迎信息，但弱化系统监控属性。

#### 2. 我的工作摘要卡片

展示聚合数字卡片：

1. 当前待办数。
2. 当前待阅数。
3. 我负责的项目数。
4. 我参与的项目数。
5. 即将到期事项数。
6. 已逾期事项数。

这些卡片应支持点击跳转到消息中心、项目列表或相关业务列表页。

#### 3. 我的待办与待阅

以列表或双栏卡片展示：

1. 最近待办事项。
2. 最近待阅消息。

数据优先复用消息中心现有接口与结构，避免重新定义审批/消息数据模型。

#### 4. 我参与的项目

展示用户当前关注的项目集合，建议优先展示：

1. 我负责的项目。
2. 我参与的项目。
3. 需关注项目。

每个项目卡片展示最少信息：

1. 项目名称。
2. 当前状态。
3. 进度。
4. 风险/健康度提示。
5. 进入项目详情或项目驾驶舱的快捷入口。

#### 5. 个人快捷入口

提供用户高频操作入口，例如：

1. 消息中心。
2. 项目列表。
3. 知识中心。
4. 个人中心。

这个区域强调“常用工作入口”，避免出现大量系统管理菜单。

## 系统首页设计

### 页面目标

系统首页服务“系统管理者现在该关注什么”的视角，突出系统状态、管理动作与后台入口。

### 页面结构

建议系统首页按以下区域组织。

#### 1. 顶部系统概览区

展示：

1. 系统版本。
2. 更新时间。
3. 当前在线人数。
4. 今日访问量或访问趋势摘要。

这部分可直接复用当前首页已经存在的系统统计能力。

#### 2. 管理工作摘要卡片

展示管理员需要快速感知的数字卡片：

1. 在线用户数。
2. 今日登录量。
3. 未读系统消息数。
4. 当前待审批/待处理管理事项数。

卡片点击后应能跳转到对应管理页面。

#### 3. 系统管理快捷入口

作为系统首页核心区域，集中展示后台管理入口：

1. 用户管理。
2. 角色管理。
3. 菜单管理。
4. 系统配置。
5. 在线用户。
6. 登录日志。
7. 系统日志。

这个区域应以明显的“操作入口区”形式呈现，而不是简单文字列表。

#### 4. 系统趋势与监控

保留并整理现有首页系统统计模块：

1. 访问趋势。
2. 用户地区分布。

如果版面有限，系统首页优先保证管理入口和管理摘要可见，再展示趋势图表。

#### 5. 业务监控摘要

可选保留少量业务层指标，例如项目总数、需关注项目数或未处理提醒数，但只作为补充信息。

系统首页的重点仍应是“系统管理”，而不是再变成用户工作台。

## 导航与入口策略

1. 左侧导航中显示两个页面：
   - 首页
   - 系统首页
2. 对没有 `dashboard/adminIndex` 权限的用户：
   - 不显示“系统首页”菜单
   - 直接访问 `/adminindex` 时应被现有权限体系拦截
3. 已有首页跳转逻辑、面包屑和返回首页按钮默认仍指向 `/` 或首页路由，需要在实现阶段核对其最终落点是否仍符合预期。

## 数据来源策略

优先复用已有接口，不在一开始就引入新的聚合接口。

### 用户首页优先复用

1. 消息中心相关接口，用于待办/待阅。
2. 项目列表或项目驾驶舱接口，用于参与项目展示。
3. 当前首页基础接口，用于少量通用指标。

### 系统首页优先复用

1. 当前首页 `getIndexCountData`。
2. 在线用户与登录日志统计接口。
3. 消息中心未读数接口。

只有在以下情况成立时，才建议新增后端首页聚合接口：

1. 页面请求数量过多。
2. 首屏耗时明显偏高。
3. 前端组合逻辑过重，导致维护成本上升。

## 实现边界

建议实现阶段采用最小改动策略：

1. 复用现有 `views/index/index.vue` 作为用户首页基础。
2. 新增一个系统首页页面文件，例如：
   - `views/index/adminindex.vue`，或
   - `views/adminindex/index.vue`
3. 在路由中显式增加 `/adminindex`。
4. 只在明确重复的场景下抽公共卡片组件。
5. 保持现有页面风格一致，不额外引入新的复杂布局系统。

## 风险与控制

1. 风险：两个首页重复代码过多。
   - 控制：仅对真正重复的卡片或块做抽取，不提前过度封装。

2. 风险：系统首页权限模型不清晰。
   - 控制：增加独立权限字符 `dashboard/adminIndex`，以角色配置为准。

3. 风险：用户首页请求过多、首屏变慢。
   - 控制：优先复用现有接口；实现后如发现请求过散，再补聚合接口。

4. 风险：首页路由和菜单关系调整后，已有“返回首页”或默认跳转逻辑出现不一致。
   - 控制：实现阶段统一核对 `/`、`/index`、菜单首页和面包屑首页图标行为。

## 验证目标

实现完成后应验证：

1. `/index` 正常展示用户首页。
2. `/adminindex` 正常展示系统首页。
3. 两个页面都在导航中可见。
4. 没有系统首页权限的用户看不到也打不开 `/adminindex`。
5. 用户首页能够展示待办、待阅、参与项目等信息。
6. 系统首页能够展示系统管理摘要和管理快捷入口。

## 预期结果

最终系统会形成两套职责明确的首页：

1. `首页 /index`：面向普通用户，强调个人任务、项目参与和工作入口。
2. `系统首页 /adminindex`：面向具备配置权限的管理员，强调系统状态、管理动作与后台入口。

这样可以避免当前统一首页同时服务两类目标导致的信息失焦问题，并为后续按角色继续演进首页提供稳定结构。
