# 飞书审批集成验收清单

## 目的

本清单用于验收第一期飞书审批集成：系统内审批待办发送飞书卡片，用户点击“去审批”后通过飞书登录进入系统审批页，并在审批完成后回写飞书卡片状态。

第一期不包含飞书卡片内快捷审批。

## 验收范围

必须覆盖以下链路：

1. 飞书后台应用配置
2. 系统外部通知配置
3. 系统用户与飞书账号映射
4. 工作流待办生成飞书卡片
5. 飞书卡片“去审批”进入系统审批页
6. 审批完成后更新飞书卡片状态
7. 系统内消息、飞书消息、卡片回写日志可追踪
8. 原始发送日志晚于审批状态回写时，补偿任务能继续处理
9. 过期日志清理任务不删除待补偿记录

## 环境前提

### 本地环境

本地前端地址可以是：

```text
http://localhost:1994
```

但飞书 OAuth 回调和卡片按钮必须能被飞书服务器和飞书客户端访问。只在本机浏览器使用 `localhost:1994` 不等于飞书可访问。

本地联调建议使用公网隧道地址，例如：

```text
https://your-tunnel.example.com
```

系统配置里的站点地址应填写这个公网地址，而不是只填 `localhost`。

### 服务启动

后端：

```bash
cd nest-admin
npm run dev
```

前端：

```bash
cd nest-admin-frontend
npm run dev
```

## 飞书后台配置

在飞书开放平台检查以下配置。

### 凭证与基础信息

1. 已创建企业自建应用
2. 已拿到 `App ID`
3. 已拿到 `App Secret`
4. 应用已发布到测试企业或目标企业
5. 机器人能力已启用

如果机器人能力未启用，系统发送飞书消息会返回：

```text
Bot ability is not activated. code: 230006
```

### 安全设置

进入：

```text
开发配置 → 安全设置 → 重定向 URL
```

添加系统自检展示的 `callbackUrl`，格式应类似：

```text
https://your-domain.example.com/api/auth/feishu/callback
```

如果没有配置，飞书扫码或 OAuth 登录会提示：

```text
重定向 URL 有误，错误码：20029
```

### 权限范围

至少确认以下能力可用：

1. 获取应用访问凭证
2. 通过邮箱或手机号查询用户
3. 获取用户详情
4. 发送机器人消息或卡片消息
5. OAuth 登录获取用户身份

## 系统配置

进入：

```text
系统管理 → 系统配置 → 外部通知
```

检查：

1. 外部通知总开关已启用
2. 飞书通知已启用
3. `AppId` 与飞书后台一致
4. `AppSecret` 与飞书后台一致
5. `BaseUrl` 默认为 `https://open.feishu.cn`
6. 站点地址为飞书客户端可访问地址
7. 点击“飞书配置自检”

自检通过时应至少看到：

1. 配置完整性通过
2. 站点地址通过，并展示 `callbackUrl`
3. OAuth 重定向 URL 提示可复制
4. 应用凭证获取成功
5. 用户匹配成功，展示飞书 `UserID`
6. 用户详情获取成功，展示 `OpenID`、`UnionID`、姓名
7. 外部账号映射字段完整
8. 审批免登录链接可生成
9. 卡片发送成功

## 用户账号映射

进入：

```text
系统管理 → 外部账号映射
```

对测试用户检查：

1. 平台为 `飞书`
2. 系统用户正确
3. 外部用户姓名正确
4. 外部用户 ID 为飞书 `UserID`
5. `OpenID` 已写入
6. `UnionID` 已写入
7. 绑定状态为启用

如果飞书接口报：

```text
The request you send is not a valid user_id or not exists
```

优先检查发送消息使用的是 `UserID` 还是 `OpenID`，当前系统应以 `UserID` 作为主要接收人 ID。

## 审批卡片验收

### 发起审批

1. 使用测试用户创建一条需要审批的业务单据
2. 提交审批
3. 确认系统内消息中心产生待办消息
4. 确认飞书收到审批卡片
5. 卡片中应展示业务标题、节点、发起人等关键信息
6. 卡片中应有“去审批”按钮

### 点击去审批

未登录系统时：

1. 在飞书中点击“去审批”
2. 进入飞书授权或扫码登录
3. 登录成功后跳转到系统审批页
4. 审批页应显示当前业务详情和审批面板
5. 当前审批人为登录用户时，应可审批

已登录系统时：

1. 点击“去审批”
2. 应直接进入审批页
3. 不应重复要求账号密码登录

异常用户：

1. 飞书用户未绑定系统用户时，应提示“飞书账号未绑定系统用户”
2. 当前用户不是审批人时，应显示当前待办办理人，不允许审批
3. 任务已处理时，应显示只读流程图和历史记录

### 完成审批

审批完成后检查：

1. 系统审批状态已更新
2. 系统内消息角标刷新
3. 页面不再弹出“几秒后自动返回上一页”的弹窗
4. 飞书原卡片状态更新为已完成、已驳回或已转交
5. 已完成卡片再次点击时，应进入只读详情或给出明确提示

## 日志验收

进入：

```text
系统管理 → 外部通知日志
```

按同一个统一消息 ID 检查三类记录：

1. 系统内消息投递日志
2. 飞书消息发送日志
3. 飞书卡片状态回写日志

每条日志至少确认：

1. 平台正确
2. 状态正确
3. 接收人 ID 正确
4. 外部用户 ID 正确
5. 统一消息 ID 一致
6. 外部消息 ID 已记录
7. 请求摘要可定位业务来源
8. 失败时错误信息完整

## 补偿任务验收

用于验证“用户审批太快，原始飞书发送日志还没写入，状态回写不会丢失”。

检查方式：

1. 构造或观察一条待补偿的飞书卡片状态日志
2. 日志状态应为待补偿或等待处理
3. 等原始飞书发送日志写入后，补偿任务应找到外部消息 ID
4. 补偿成功后应新增或更新卡片回写成功日志
5. 待补偿记录不应被清理任务提前删除

定时任务位置：

```text
系统管理 → 定时任务
```

关注任务：

1. 飞书卡片状态补偿任务
2. 通知投递日志清理任务

## 常见问题

### 错误码 20029

原因：飞书后台未配置当前系统的 OAuth 回调地址。

处理：

1. 打开飞书后台
2. 进入 `开发配置 → 安全设置 → 重定向 URL`
3. 添加系统自检结果中的 `callbackUrl`
4. 重新发布或保存应用配置

### 错误码 230006

原因：飞书机器人能力未启用。

处理：

1. 打开飞书后台应用能力配置
2. 启用机器人
3. 确认应用已发布到测试企业或目标企业
4. 重新发送自检卡片

### 错误码 99992360

原因：接收人 ID 类型不匹配，或用户不存在。

处理：

1. 重新同步外部账号映射
2. 确认外部用户 ID 为飞书 `UserID`
3. 确认 `OpenID` 和 `UnionID` 已保存
4. 重新执行飞书配置自检

## 最小验收通过标准

满足以下条件可认为第一期可进入更大范围试用：

1. 飞书配置自检通过
2. 测试用户账号映射字段完整
3. 发起审批后飞书能收到卡片
4. 点击“去审批”能免账号密码进入审批页
5. 审批完成后系统状态正确
6. 审批完成后飞书卡片状态正确回写
7. 外部通知日志能按统一消息 ID 串起系统内消息、飞书发送、卡片回写
8. 补偿任务可以处理原始日志晚写入场景
9. 日志清理任务不会删除待补偿记录
