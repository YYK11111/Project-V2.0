1. 字段在什么时候赋值
2. 字段通过什么途径赋值
3. 当前赋值逻辑是否已经实现
4. 新建项目视图显示的字段是否有缺失或多余
5. `阶段开始 / 阶段结束` 当前的业务作用和实现状态

1. 前端页面

## 2. 当前项目表单的赋值链路

### 2.1 初始化赋值

来源：

`createDefaultForm()`

当前已实现：

1. 项目基础字段默认值
2. 时间字段默认值
3. 基线计划字段默认值
4. 经营字段默认值
5. 结项字段默认值
6. 成员默认一条
7. 里程碑按项目类型生成默认模板

结论：

初始化逻辑已实现，且结构完整。

### 2.2 新建态赋值

来源：

1. `createDefaultForm()`
2. `watch(projectType)`
3. `watch(leaderId)`
4. `normalizeSubmitPayload()`

当前已实现：

1. `projectType` 变化时，在未手动修改里程碑模板的前提下，自动按项目类型生成默认里程碑
2. `leaderId` 变化时，如果负责人不在成员列表中，会自动补一条项目经理角色成员
3. 提交新建时，系统会自动修正以下字段：
   - `phase = 'init'`
   - `status = '1'`
4. 提交新建时，系统会清空执行期和结果期字段：
   - `actualStartDate`
   - `actualEndDate`
   - `phaseStartDate`
   - `phaseEndDate`
   - `actualCost`
   - `spentHours`
   - `riskLevel`
   - `qualityLevel`
   - `closeSummary`
   - `closeDeliverables`
   - `closeOpenIssues`
   - `closeReview`
   - `acceptanceDate`
5. 提交新建时，成员列表会裁剪成最小结构：
   - `userId`
   - `role`
   - `isCore`
   - `sort`
6. 提交新建时，里程碑列表会裁剪成最小结构：
   - `name`
   - `dueDate`
   - `sort`

结论：

新建态赋值和提交前裁剪逻辑已实现，而且整体方向正确。

### 2.3 编辑态赋值

来源：

`loadProject()`

当前已实现：

1. 通过 `getOne(id)` 获取项目详情
2. 将后端项目详情整体回填到 `form.value`
3. 若成员或里程碑为空，则补默认结构
4. 通过 `getFieldPermissions(id)` 获取字段组权限结果

结论：

编辑态回填逻辑已实现。

## 3. `阶段开始 / 阶段结束` 的作用和当前实现状态

### 3.1 字段定义

对应字段：

1. `phaseStartDate`
2. `phaseEndDate`

定义位置：

`nest-admin/src/modulesBusi/projects/entity.ts`

字段含义：

1. 当前项目阶段开始时间
2. 当前项目阶段结束时间

### 3.2 业务作用

它们更适合用于：

1. 项目阶段切换跟踪
2. 阶段级超期提醒
3. 驾驶舱阶段分析
4. 阶段健康度和阶段偏差判断

### 3.3 当前实现状态

当前没有发现自动赋值逻辑。

已确认情况：

1. 前端默认初始化为空
2. 编辑已有项目时，如果后端有值则回填显示
3. 新建项目提交时，会被强制清空
4. 后端服务中没有发现基于 `phase` 自动写入这两个字段的逻辑
5. 也没有发现基于阶段切换、工作流节点或状态变更自动维护这两个字段的逻辑

结论：

1. 字段本身已落地
2. 但业务逻辑尚未闭环
3. 当前只能理解为“人工维护的阶段时间窗口字段”
4. 现阶段不适合在新建项目页展示

### 3.4 最合理的赋值时机

如果后续继续完善，建议考虑以下三种方式中的一种：

1. 阶段切换时自动赋值
   - 切换到新阶段时自动填 `phaseStartDate`
   - 切出旧阶段时自动补 `phaseEndDate`

2. 编辑已有项目时人工维护
   - 只在编辑页对已有项目开放
   - 明确其含义为“当前阶段窗口”

3. 暂时不启用
   - 保留字段，但隐藏新建态和普通编辑态
   - 等二期阶段治理完善后再启用

## 4. 新建项目页当前显示字段复查

### 4.1 当前合理保留的字段

建议新建项目页保留：

1. `name`
2. `code`（只读）
3. `departmentId`
4. `category`
5. `projectType`
6. `tags`
7. `creatorId`
8. `leaderId`
9. `priority`
10. `customerId`
11. `startDate`
12. `endDate`
13. `baselineDeliverables`
14. `scopeBoundary`
15. `baselinePlanNote`
16. 精简成员字段
17. 精简里程碑字段
18. `description`
19. `attachments`

### 4.2 当前明确多余的字段

当前复查确认，新建态不应该出现但仍可能出现或曾经出现过的字段主要有：

1. `phaseStartDate`
2. `phaseEndDate`

原因：

1. 新建提交时会被清空
2. 和项目整体时间字段概念重叠
3. 当前没有自动赋值逻辑支撑

### 4.3 当前可能缺失的字段

从业务角度看，有一类字段可能需要你进一步拍板：

1. `budget`
2. `currency`

当前状态：

1. 新建态隐藏了经营结果类字段
2. 这在“后置经营录入”模式下是合理的
3. 但如果业务要求立项阶段同步给出预算，则这两个字段会成为新建页的缺失字段

结论：

是否恢复新建态预算和币种，取决于业务口径，而不是代码正确性问题。
