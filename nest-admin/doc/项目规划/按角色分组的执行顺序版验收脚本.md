# 按角色分组的执行顺序版验收脚本

本文档基于以下两份清单整理：

1. `项目字段组权限第一版验收清单.md`
2. `整个项目管理体系权限验收清单.md`

目标是把验收动作整理成一套可以直接执行的脚本，适合测试、产品、项目经理或开发联调时逐项勾选。

## 1. 使用说明

执行原则：

1. 先用管理员完成环境与基线准备
2. 再按角色从高到低执行
3. 每个角色优先走“项目主链路”
4. 再走“风险/变更/工单/知识”链路
5. 最后走负向场景和导出场景

建议顺序：

1. 超级管理员
2. 项目经理
3. 交付经理
4. 负责人类角色
5. 普通成员
6. 访客
7. 知识管理员

## 2. 前置准备脚本

由超级管理员执行。

### 2.1 环境确认

1. 打开系统，确认可以正常登录
2. 确认数据库已有测试项目
3. 确认测试项目下已有：
   项目成员
   里程碑
   任务
   Sprint
   风险
   变更
   工单
   知识目录
   知识文章

### 2.2 账号确认

准备以下账号：

1. 超级管理员
2. 项目经理
3. 交付经理
4. 负责人类角色
5. 普通成员
6. 访客
7. 知识管理员

### 2.3 项目状态确认

准备三类项目：

1. 草稿或未审批项目
2. 审批中项目
3. 已结项或已归档项目

### 2.4 基线矩阵确认

使用超级管理员进入：

`系统配置 -> 字段组权限`

检查矩阵是否为当前预期值。

## 3. 超级管理员执行脚本

### 3.1 系统配置页

1. 进入 `系统配置 -> 字段组权限`
2. 检查矩阵列：
   `基础组`
   `成员组`
   `计划组`
   `经营组`
   `结项组`
   `知识组`
3. 检查矩阵行：
   `项目经理`
   `交付经理`
   `负责人类角色`
   `普通成员`
   `访客`
4. 修改一个单元格，例如：
   `member -> projectBusiness -> hidden`
5. 点击保存
6. 刷新页面
7. 确认值仍然存在
8. 恢复原值并再次保存

### 3.2 项目主链路基线确认

1. 进入 `projectManage/form`
2. 进入 `projectManage/detail`
3. 进入 `projectManage/approval`
4. 确认超级管理员可完整看到所有区块
5. 修改主表字段、成员、里程碑并保存
6. 确认不会被字段组权限拦截

### 3.3 知识回流全链路确认

1. 进入风险详情，执行 `转知识`
2. 进入变更详情，执行 `转知识`
3. 进入工单详情，执行 `转知识`
4. 打开知识详情页，点击 `查看来源`
5. 确认可返回来源对象页面

### 3.4 导出能力确认

依次进入：

1. 知识列表
2. 风险列表
3. 变更列表
4. 工单列表
5. 项目成员列表
6. 里程碑列表
7. Sprint 列表
8. 项目驾驶舱

逐一点击导出，确认：

1. 文件可下载
2. 文件非空
3. 列头完整
4. 数据与页面一致

## 4. 项目经理执行脚本

### 4.1 项目表单

1. 登录项目经理账号
2. 打开测试项目 `projectManage/form`
3. 检查：
   基础组可见可编辑
   成员组可见可编辑
   计划组可见可编辑
   经营组可见可编辑
   结项组可见可编辑
4. 分别修改以下内容并保存：
   项目名称
   项目成员
   里程碑
   项目预算
   结项资料
5. 确认全部保存成功

### 4.2 项目详情

1. 打开 `projectManage/detail`
2. 检查：
   项目知识入口可见
   结项入口可见
   项目成员表可见
3. 点击：
   `新增知识`
   `结项资料`
4. 确认可进入对应页面或对应 tab

### 4.3 审批页

1. 打开 `projectManage/approval`
2. 检查：
   基本信息可见
   项目成员可见
   里程碑计划可见
   项目描述与附件可见

### 4.4 项目知识

1. 从项目详情进入知识空间
2. 执行新增知识
3. 打开知识详情
4. 检查来源字段与反向跳转

## 5. 交付经理执行脚本

### 5.1 项目表单

1. 登录交付经理账号
2. 打开 `projectManage/form`
3. 检查：
   基础组只读
   成员组可编辑
   计划组可编辑
   经营组只读
   结项组可编辑

### 5.2 保存校验

逐项执行：

1. 修改成员并保存
   预期：成功
2. 修改里程碑并保存
   预期：成功
3. 修改预算并保存
   预期：失败
4. 修改成本并保存
   预期：失败
5. 修改结项资料并保存
   预期：成功

### 5.3 详情与审批页

1. 打开详情页
2. 检查成员、计划、结项、知识入口均可见
3. 打开审批页
4. 确认项目成员、里程碑计划、描述附件可见

## 6. 负责人类角色执行脚本

### 6.1 项目表单

1. 登录负责人类账号
2. 打开 `projectManage/form`
3. 检查：
   基础组只读
   成员组只读
   计划组只读
   经营组隐藏
   结项组只读

### 6.2 保存负向场景

逐项执行：

1. 修改基础字段并保存
   预期：失败
2. 修改成员并保存
   预期：失败
3. 修改里程碑并保存
   预期：失败
4. 尝试查看经营字段
   预期：看不到

### 6.3 详情页

1. 打开详情页
2. 检查：
   知识入口可见
   结项入口可见
   经营信息不应暴露为可编辑入口

## 7. 普通成员执行脚本

### 7.1 项目表单

1. 登录普通成员账号
2. 打开 `projectManage/form`
3. 检查：
   基础组只读
   成员组只读
   计划组只读
   经营组隐藏
   结项组隐藏

### 7.2 负向保存

1. 修改基础字段
   预期：失败
2. 修改成员
   预期：失败
3. 修改里程碑
   预期：失败

### 7.3 详情页

1. 打开详情页
2. 检查：
   项目知识入口可见但不一定可新增
   结项页签隐藏
   项目成员表可见

## 8. 访客执行脚本

### 8.1 项目表单

1. 登录访客账号
2. 打开 `projectManage/form`
3. 检查：
   基础组只读
   成员组隐藏
   计划组隐藏
   经营组隐藏
   结项组隐藏

### 8.2 项目详情

1. 打开详情页
2. 检查：
   核心成员摘要不显示实际成员列表
   项目成员表不显示
   知识 tab 可见
   结项 tab 隐藏

### 8.3 审批页

若访客理论上无审批访问权：

1. 直接访问审批页
2. 预期：禁止访问或页面无相关操作入口

## 9. 知识管理员执行脚本

### 9.1 知识列表与详情

1. 登录知识管理员
2. 打开知识列表
3. 检查来源列：
   `来源类型`
   `来源项目ID`
   `来源对象ID`
   `模板类型`
4. 打开知识详情
5. 点击 `查看来源`
6. 确认能跳转到来源对象

### 9.2 知识回流对象核查

1. 到风险列表看 `知识回流` 状态
2. 到变更列表看 `知识回流` 状态
3. 到工单列表看 `知识回流` 状态
4. 点击 `查看知识`
5. 确认正确跳转

## 10. 负向攻击脚本

由开发或测试执行。

### 10.1 前端绕过保存

1. 用普通成员账号抓包或改请求体
2. 强行提交：
   `budget`
   `actualCost`
   `closeReview`
3. 预期：后端拒绝

### 10.2 子表绕过保存

1. 强行构造 `members` 变更请求
2. 强行构造 `milestones` 变更请求
3. 预期：后端拒绝

### 10.3 知识回流绕过

1. 无知识权限账号尝试调用转知识接口
2. 预期：拒绝或前端无入口

## 11. 执行记录建议

每执行完一个角色，记录：

1. 角色名称
2. 账号
3. 覆盖页面
4. 通过项
5. 未通过项
6. 截图或接口报错
7. 责任人
8. 是否阻塞上线

## 12. 推荐执行顺序

建议按以下顺序实际执行：

1. 超级管理员
2. 项目经理
3. 交付经理
4. 负责人类角色
5. 普通成员
6. 访客
7. 知识管理员
8. 负向攻击脚本

理由：

1. 先验证配置和基线正确
2. 再验证高权限到低权限的差异
3. 最后验证安全兜底
