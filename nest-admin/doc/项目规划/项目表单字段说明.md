# 项目表单字段说明

本文档用于说明 `projectManage/form.vue` 当前项目表单中的字段含义、出现阶段以及在新建项目时的建议展示策略。

## 1. 关于“阶段开始 / 阶段结束”的作用

### 1.1 字段定义

1. `phaseStartDate`
   - 含义：当前项目阶段的开始时间

2. `phaseEndDate`
   - 含义：当前项目阶段的结束时间

### 1.2 和其他时间字段的区别

项目表单当前存在四类时间概念：

1. `startDate / endDate`
   - 项目整体基准时间
   - 更适合立项时填写

2. `planStartDate / planEndDate`
   - 项目级计划时间
   - 用于后续计划/实际偏差分析

3. `actualStartDate / actualEndDate`
   - 项目实际执行时间
   - 用于执行审计和偏差复盘

4. `phaseStartDate / phaseEndDate`
   - 当前所处阶段的时间窗口
   - 用于阶段管理，比如：
     `立项阶段`
     `实施阶段`
     `验收阶段`
     `结项阶段`

### 1.3 业务作用

这两个字段更适合服务以下场景：

1. 项目阶段切换跟踪
2. 项目驾驶舱的阶段分析
3. 阶段超期提醒
4. 阶段级别的健康度和执行偏差判断

### 1.4 是否适合在新建项目时展示

不适合。

原因：

1. 新建项目默认就是 `立项阶段`
2. 此时用户已经填写了 `startDate / endDate`
3. 再额外填写 `phaseStartDate / phaseEndDate` 容易与项目整体时间重复
4. 这两个字段更适合在项目创建后、阶段切换时维护

结论：

1. 新建项目时建议隐藏
2. 编辑已有项目时再显示

## 2. 当前项目表单字段总览

### 2.1 项目基础信息

1. `name`
   - 项目名称
   - 新建必填

2. `code`
   - 项目编号
   - 系统生成
   - 新建时只读显示即可

3. `departmentId`
   - 所属部门
   - 新建必填

4. `category`
   - 项目分类
   - 新建建议填写

5. `projectType`
   - 项目类型
   - 新建必填

6. `tags`
   - 项目标签
   - 新建可选

7. `creatorId`
   - 项目发起人
   - 新建必填

8. `leaderId`
   - 项目负责人
   - 新建必填

9. `priority`
   - 优先级
   - 新建建议填写

10. `phase`
   - 当前项目阶段
   - 新建建议默认 `init`
   - 不建议新建页手动选择

11. `customerId`
   - 客户
   - 新建可选

12. `status`
   - 项目状态
   - 新建默认草稿/待审批
   - 不建议新建页开放修改

## 2.2 项目时间字段

1. `startDate`
   - 项目开始时间
   - 新建必填

2. `endDate`
   - 项目结束时间
   - 新建必填
   - 需校验不早于开始时间

3. `planStartDate`
   - 项目计划开始
   - 新建可隐藏
   - 编辑时显示更合理

4. `planEndDate`
   - 项目计划结束
   - 新建可隐藏
   - 编辑时显示更合理

5. `actualStartDate`
   - 项目实际开始
   - 新建应隐藏

6. `actualEndDate`
   - 项目实际结束
   - 新建应隐藏

7. `phaseStartDate`
   - 阶段开始
   - 新建应隐藏

8. `phaseEndDate`
   - 阶段结束
   - 新建应隐藏

## 2.3 立项基线计划

1. `baselineDeliverables`
   - 主要交付物
   - 新建建议必填

2. `scopeBoundary`
   - 范围边界
   - 新建建议必填

3. `baselinePlanNote`
   - 计划说明
   - 新建可选

## 2.4 项目成员

1. `members[].userId`
   - 成员用户
   - 新建建议保留

2. `members[].role`
   - 项目角色
   - 新建建议保留

3. `members[].isCore`
   - 是否核心成员
   - 新建建议保留

4. `members[].joinDate`
5. `members[].notificationEnabled`
6. `members[].responsibilityScope`
7. `members[].positionTitle`
8. `members[].leaveDate`
9. `members[].fieldPermissionGroup`
10. `members[].remark`

这些字段更适合：

1. 项目创建成功后再维护
2. 不建议在新建页完整展开

## 2.5 里程碑计划

1. `milestones[].name`
   - 里程碑名称
   - 新建建议保留

2. `milestones[].dueDate`
   - 计划完成日期
   - 新建建议保留

3. `milestones[].ownerId`
4. `milestones[].phase`
5. `milestones[].status`
6. `milestones[].deliverables`
7. `milestones[].description`
8. `milestones[].delayReason`
9. `milestones[].changeImpactFlag`
10. `milestones[].riskImpactFlag`

这些字段更适合：

1. 项目创建成功后补充
2. 新建页不建议完整展开

## 2.6 项目描述与附件

1. `description`
   - 项目描述
   - 新建建议保留

2. `attachments`
   - 项目附件
   - 新建建议保留

## 2.7 经营信息

1. `budget`
   - 项目预算
   - 新建可选

2. `actualCost`
   - 实际成本
   - 新建应隐藏

3. `currency`
   - 币种
   - 新建可默认 `CNY`

4. `riskLevel`
   - 整体风险等级
   - 新建应隐藏或后置

5. `qualityLevel`
   - 整体质量等级
   - 新建应隐藏或后置

6. `businessLine`
   - 业务线
   - 新建可选

7. `industry`
   - 行业
   - 新建可选

8. `projectSource`
   - 项目来源
   - 新建可选

9. `spentHours`
   - 累计工时
   - 新建应隐藏

10. `progress`
    - 项目进度
    - 系统计算
    - 不应在新建页人工维护

## 2.8 结项资料与复盘

1. `acceptanceDate`
2. `closeSummary`
3. `closeDeliverables`
4. `closeOpenIssues`
5. `closeReview`

这些字段都属于结项阶段字段。

结论：

1. 新建项目页面不应显示
2. 编辑已有项目时显示
3. 发起结项审批前再补齐

## 3. 新建项目页面建议保留字段

建议新建页只保留：

1. 项目名称
2. 所属部门
3. 项目分类
4. 项目类型
5. 项目标签
6. 项目发起人
7. 项目负责人
8. 优先级
9. 客户
10. 开始时间
11. 结束时间
12. 主要交付物
13. 范围边界
14. 计划说明
15. 精简版成员
16. 精简版里程碑
17. 项目描述
18. 项目附件

## 4. 新建项目页面建议隐藏字段

1. `phase`
2. `planStartDate`
3. `planEndDate`
4. `actualStartDate`
5. `actualEndDate`
6. `phaseStartDate`
7. `phaseEndDate`
8. `status`
9. `actualCost`
10. `riskLevel`
11. `qualityLevel`
12. `spentHours`
13. 全部结项字段
14. 成员治理扩展字段
15. 里程碑执行扩展字段

## 5. 建议

建议后续继续做两类优化：

1. 新建态和编辑态彻底分离
2. 立项类字段与执行类字段进一步按区块拆分
